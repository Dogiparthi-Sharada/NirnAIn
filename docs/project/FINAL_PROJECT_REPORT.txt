1. Executive summary

On the morning of November 13 the project was stalled. Production was down (Railway answered 404, a keep-alive job had failed since October 26, and the Supabase project no longer existed). Two pull requests were open: AI intake with Claude (upstream PR #18, CI green) and a Gurobi planning draft on the product owner's fork (failing checks).

The goal was a working demo within about a day, hosted for free, that looks exactly like the approved clickable mockup "and logic accordingly".

Result. All seven planning steps, the dashboard, the landing page and sign-in work on live data and look like the mockup:

• AI intake with quotes, and a rule-based fallback when there is no key.
• A WBS builder with confirmed estimates and skill tags.
• Constraints with Must hold / Can flex.
• An OR-Tools CP-SAT optimizer that names every blocker and offers priced ways to keep a date.
• Plan versions (v1 → v2 …) with step-7 change handling.

The product owner's QA pack and the lead's test suites found four P0 defects; all four are fixed. The API scenario suite went from 194 PASS / 13 FAIL to 236 PASS / 1 FAIL, and the backend's automated tests grew from 358 to 511. QA used 0 Claude tokens. A step-by-step guide hosts the demo for free on Render and a new Supabase project.

4. Scope delivered, by step

• Public pages: Landing page, sign-in, sign-up (at least 10 characters, upper and lower case, a digit), forgot / reset password. Google / Microsoft buttons show only when the provider is enabled.
• Dashboard: Project picker; next step; progress; budget with planned cost and headroom; milestones; open risks; delivery health (status, due date, next milestone, peak utilization, constraint violations, constraint choices, "spent to date: not tracked yet"); notifications.
• 1 · Create Project: A validated form, or upload / paste notes to pre-fill it: each field shows its quote and whether it was stated, inferred or missing. Nothing is saved until you confirm.
• 2 · AI Project Intake: Paste notes and upload PDF, Word and transcripts (.vtt, .srt, .txt) up to 100 MB. Video is refused with a note; audio shows "coming soon". Runs in the background; shows what was found by evidence type, and previous intakes.
• 3 · Scope Review: Six categories (objectives, requirements, deliverables, constraints, risks, missing info). Accept, edit or remove each item, with the source quote under it. "Accept all quoted"; add items by hand; a "Removed" group with Undo. Pending items block step 4.
• 4 · WBS Builder: A three-level tree (chart or list view). Deliverables and work packages, durations in weeks (stored as working days), owners, skill tags. Confirm AI estimates; generate (Claude or a template); validate (built-in checks plus an optional Claude review).
• 5 · Constraints: "Questions that change the plan" (outside specialist and rate, hard deadline). The team: Employee or Contractor, hours per week, skills. Required / optional skills; dependencies FS/SS/FF/SF with lag. Budget, deadline, capacity and skills as Must hold / Can flex, with recommendations and warnings; reserve, caps, milestones.
• 6 · Optimization Results: "Check the inputs" sheet (each value's source, blocking reasons) → run. Cost, finish date, utilization, critical path, constraint check, timeline, reassignments, schedule changes and utilization. "Ways to keep the date" (contractor, overtime, accept) priced; infeasible runs name every blocker. Apply as Plan vN; "Inputs changed since Plan vN" and "Run again"; PDF and MS Project exports.
• 7 · Changes & Versions: New meeting notes (Claude or rules), direct edits, or a progress update → questions, impact, re-plan from today with minimal disruption, ways to keep the date, a day-level comparison of Plan vN+1 with vN. Approve or keep the current plan; add or remove people; the version list.
• AI side panel: The planning assistant answers questions about the project with Claude ("unavailable" without a key).

The demo seed (Jane Doe, jane.doe@nirnain.demo) fills a workspace with five projects that cover every stage: a draft, one in planning, two with Plan v1 applied, and the walkthrough project Enterprise Data Platform with Plan v1 → Plan v2. The v2 came from the Steering Committee note "Tom Rivera can give this project only 24 hours a week".

The product owner's QA pack (NirnAIn_QA_Pack_Gurobi: 217 cases, meetings M01 → M03)

• 1 · Journey (M01 → v1 → M02 → v2 → M03) and solver matrices, SOLVE / CHANGE / INTERACT / GUR (287 results) – PASS: 83. FAIL: 37. BLOCKED: 132. Not run / ignored: 35 not run (AI-only).
• 2 · AUTH, CREATE, INTAKE, SCOPE, WBS, RES, CON, VIEW, SEC, NFR and adversarial inputs (155 cases) – PASS: 81. FAIL: 16. BLOCKED: 37. Not run / ignored: 21 ignored (AI-only, PO decision).

BLOCKED means "not testable here", not "broken". It covers:

• features not built by decision;
• features the app doesn't have (roles and invitations, an audit view…);
• the pack's Gurobi-specific objective (model mismatch: the feasible / infeasible conclusion matched in all 32 matrix rows);
• test-environment limits.

Part 1's failures were fixed in round 3, and part 2 confirmed those fixes. Part 2's failures were fixed in round 4, except the items in section 6.

P0 defects found and fixed

Four P0 defects were found in total (QA pack and the lead's tests). All are fixed. The three from the QA pack:

• A plan solved before an input change could still be applied – Found by: QA pack part 1. Fix: Apply (and step-7 approve) refused with 409 when the inputs fingerprint changed; step 6 disables Apply with the reason and offers "Run again" (round 3).
• Another workspace could file dependencies on your work packages (SEC-001) – Found by: QA pack part 2. Fix: API check plus database rule: SECURITY DEFINER triggers for every link, the same error for unknown and foreign ids; pgTAP test 014 (round 4).
• A work package without a duration silently disappeared from a "ready" plan (WBS-003) – Found by: QA pack part 2. Fix: The package blocks the run, named on the inputs sheet ("… has no duration: enter one on step 4") (round 4).

Other notable fixes:

• Assignment-dependent durations: part-timers stretch tasks.
• Worker types and real costs.
• Re-plans from today.
• The reserve held back.
• Every blocker named, plus "Change these together".
• Done work stays done.
• Real booked hours on apply.
• Export hours.
• No invented values from notes.
• No user text or SQL parameters in logs.
• Double-click protection.
• Two fingerprint bugs found while merging.

The full list is in the decision log and in the QA test log (appendix).

6. Known limitations and items not supported

Not built, by product-owner decision: effective-dated availability, leave, holidays, actual hours / estimate at completion (EAC), fixed costs, Gurobi, an "as-of" clock, sub-day scheduling, audio transcription. MP4 and other video uploads are refused with a note to upload the transcript.

Not present in the app: inviting people to a workspace and assigning roles (the database has roles), an audit view, a configurable optimizer objective, renaming a workspace.

Open items (low or medium):

• B7 (low): Without Claude, "Project: … Sponsor: …" on one line isn't read when creating a project from notes. Claude handles it.
• B8 (low): Applying an already applied plan answers 422 (approving twice answers 409).
• Fingerprints after a deploy: A plan saved before a solver-logic change looks "out of date" once after the deploy. Run the optimizer again once.
• WBS validation card: Can show stale warnings after edits. The fix (live built-in checks after each edit) is on nirnain/wbs-live-checks, not merged yet.
• Small screens (NFR-003): At 390 px or 200% zoom the sidebar keeps its width and content is cut off.
• Create form (CREATE-009): A half-filled Create Project form is lost on navigation or refresh.
• A pending step-7 change (P2): It doesn't stop another run from being applied; approving the stale change afterwards is refused (409), so the review starts again.
• Sign-out (P3): The last opened project id stays in the browser's local storage (no data is shown to the next user).
• Landing page (P3): It advertises OBS / RACI, which the app doesn't have.
• Zero-day packages: A 0-day package (for example a go-live milestone) isn't scheduled as a dated milestone; the run asks for a duration.
• Contractor already on the team: By design, "outside specialist: No" stops new specialists only. Remove a contractor from the team to stop them.
• Costs: Labor only (people × hours × rate). Infrastructure isn't modelled; "spent to date" isn't tracked; employees without a company rate use the standard $85/h.
• Version history: Step 7 lists Plan v1 (superseded) and v2 (in force), but not which change created v2, and an approved change isn't listed again after a reload.
• Claude path: Not covered by QA (by decision). One small hand-run intake with the key was planned "on request" and isn't recorded as done.
• Free hosting: The Render API sleeps after 15 minutes idle (about a minute to wake). A Supabase free project pauses after a week without activity.
