NirnAIn – AI-Assisted Project Planning Platform
How the code is kept on GitHub

Authors: Sharada Dogiparthi (Team Lead), Srilekha Budithi, Rakshitha Venigella. BAN 693 Capstone Project, California State University, East Bay. Date: November 14, 2026.

All of NirnAIn's code lives in one repository, https://github.com/Dogiparthi-Sharada/NirnAIn, on the branch main. Render deploys the website and the API from main on every push, so whatever reaches main goes live within minutes. This page is the routine: clone once, then update, change, check, commit and push. Every step has a ✅ Check it worked line. Stop at the first check that fails.

Table (Item, Value):
• Repository: https://github.com/Dogiparthi-Sharada/NirnAIn (public).
• Branch: main: the only long-lived branch; Render deploys from it.
• Checks: Run them locally before every push: the CI workflow (ci.yml) is currently disabled.
• Team engineering guidelines: CONTRIBUTING.md at the root of the repository.

1. Sign in to GitHub from the terminal (once)

GitHub doesn't accept your account password for git push. Use either a personal access token over HTTPS (1A) or an SSH key (1B).

1A. HTTPS with a personal access token

1. On GitHub, click your picture → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
2. Fill in:
  ◦ Token name: nirnain-push
  ◦ Expiration: 30 days
  ◦ Resource owner: Dogiparthi-Sharada
  ◦ Repository access: Only select repositories → NirnAIn
  ◦ Permissions → Repository permissions:
    ▪ Contents: Read and write (needed to push)
    ▪ Workflows: Read and write (needed only when you change a file in .github/workflows/)
    ▪ Metadata: Read-only (added automatically)
3. Click Generate token and copy it right away. GitHub shows it only once. Keep it in your password manager, never in a file in the repository.
  A teammate added as a collaborator? A fine-grained token only reaches repositories its owner owns, so use SSH (1B) or a classic token instead: Tokens (classic) → Generate new token (classic) with the scopes public_repo (or repo) and workflow. The repository owner adds collaborators under Settings → Collaborators.
4. Make git remember the token for one hour, in memory only (not on disk):
      git config --global credential.helper 'cache --timeout=3600'
5. Test it. When git asks, enter your GitHub user name, and paste the token as the password:
      git ls-remote https://github.com/Dogiparthi-Sharada/NirnAIn.git HEAD

✅ Check it worked: one line with a 40-character commit hash followed by HEAD. "Authentication failed" means the user name or token is wrong, or the token doesn't include this repository.

1B. SSH key (alternative)

Create a key: press Enter to accept the file name, and choose a passphrase. Then show the public key and copy the whole line it prints:

    ssh-keygen -t ed25519 -C "<your-email>"
    cat ~/.ssh/id_ed25519.pub

On GitHub: Settings → SSH and GPG keys → New SSH key, paste the line, then Add SSH key. Then:

    ssh -T git@github.com

✅ Check it worked: it answers Hi <your-user-name>! You've successfully authenticated…. With SSH, use the address git@github.com:Dogiparthi-Sharada/NirnAIn.git in step 2.

2. Clone the repository (once)

    git clone https://github.com/Dogiparthi-Sharada/NirnAIn.git
    cd NirnAIn
    git status

✅ Check it worked: git status says On branch main and Your branch is up to date with 'origin/main'.

For the checks in step 4, install the tools once: pnpm install for the website and cd backend && uv sync for the API (README.md, "Quick start").

3. Update before you start

    git switch main
    git pull --ff-only

✅ Check it worked: Already up to date., or a list of the files that changed. "Not possible to fast-forward" means you have commits that aren't on GitHub yet: run git pull --rebase, then the checks of step 4 again.

4. Make the change, then run the checks

The CI workflow is currently disabled, so these checks are the only gate before your change goes live. Run them from the repository root:

    pnpm exec tsc --noEmit -p . && pnpm build
    cd backend && uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest && cd ..

• A database change is a new file in supabase/migrations/ (supabase migration new <name>); never edit a merged migration. The database tests (pgTAP) need Docker: supabase start && supabase test db.
• Code moved or renamed? Regenerate the feature-to-code map: python3.12 scripts/build_code_index.py, and commit the new INDEX.txt with your change.
• A bigger change? Work on a feature branch (git switch -c feat/<area>-<thing>) and merge it into main only when every check passes, as CONTRIBUTING.md describes.

✅ Check it worked: every command finishes without an error, and pytest ends with passed and no failed.

5. Commit

    git status --short
    git add <file> <file>
    git commit -m "fix(api): say what changed and why"

• Name the files you add. Don't use git add ., git add -A or git commit -a: they also pick up local files that must never be uploaded (next step).
• Use a conventional commit message: feat(web): …, fix(api): …, docs: …, test(db): ….

✅ Check it worked: git log --oneline -1 shows your commit, and git status --short lists nothing you meant to commit.

6. Secret checks before every push

Untracked files are never uploaded; only commits are. These must never end up in a commit:

• Any .env file (.env.local, backend/.env, supabase/.env, …) – Why: Real keys and passwords. How it stays out: .gitignore ignores .env*; only the .env.example templates are tracked.
• Token files and the data of a local Supabase stand-in – Why: Passwords, keys and database files. How it stays out: Keep them outside the repository folder.
• .vscode/ and *.code-workspace – Why: Your editor's local settings and paths. How it stays out: Never git add them.
• Hand-off archives (*.zip, for example the mockup or the QA pack) – Why: Large files, not source code. How it stays out: Never git add them; share them separately.

6.1 No secret file in your commits

    git fetch origin
    git diff --name-only origin/main...HEAD | grep -E -i '(^|/)\.env|\.zip$|code-workspace|\.vscode/|secret|token'

✅ Check it worked: nothing is printed, or only a .env.example template or backend/tests/support/tokens.py (test code that makes fake tokens, no real keys).

6.2 No key in your commits or in the code

    PATTERN='sk-ant-[A-Za-z0-9_-]{20,}|sb_secret_[A-Za-z0-9_-]{16,}|github_pat_[A-Za-z0-9_]{20,}|ghp_[A-Za-z0-9]{20,}|eyJ[A-Za-z0-9_-]{20,}\.eyJ[A-Za-z0-9_-]{20,}|BEGIN [A-Z ]*PRIVATE KEY'
    git log -p origin/main..HEAD | grep -n -E "$PATTERN"
    git grep -n -I -E "$PATTERN" HEAD

✅ Check it worked: both commands print nothing: no Claude key, Supabase secret key, GitHub token, signed token or private key.

If a check finds something, don't push. Undo the commit with git reset --soft origin/main, unstage the file with git restore --staged <path>, and commit again without it. If a real key ever reached GitHub, rotate it at once (Anthropic Console, Supabase or GitHub settings): deleting it from git later isn't enough.

7. Push to main

    git push origin main
    git ls-remote origin main
    git rev-parse main

✅ Check it worked: the push ends with main -> main, and the last two commands print the same 40-character hash.

• rejected … (fetch first): someone pushed first. Run git pull --rebase, the checks of step 4 again, then push.
• refusing to allow a Personal Access Token to create or update workflow: your token lacks the Workflows permission (or the classic workflow scope).

8. After the push

• Render redeploys the website and the API from main by itself. The API rebuilds only for changes under backend/. Follow it in the Render dashboard (each service's Events and Logs).
• A new migration isn't applied by the push. Run npx supabase@latest db push --remote (DEPLOY_DEMO.txt, step 1.5).
• The daily keep-alive stays on as long as the repository has commits: GitHub disables scheduled workflows in a public repository after 60 days without any. Re-enable it under Actions → the keep-alive workflow → Enable workflow.

✅ Check it worked: a few minutes after an API change, https://nirnain-api.onrender.com/health shows your commit (the output of git rev-parse main) as its version.

Afterwards

Clear the cached token with git credential-cache exit. Delete the token on GitHub (Settings → Developer settings → Personal access tokens → Delete) once you no longer need it, or let it expire.
